# Codex runtime integration

`@zamolxis/runtime-codex` implements AgentRuntime over a local Codex app-server stdio connection. Runtime selection and model selection remain separate. The Node validates the workspace before launch; the adapter preserves the supplied Run, workstation, workspace, branch and HEAD assignment and rejects conflicting retries.

Start initializes the protocol, creates a native thread in the assigned absolute cwd, captures its identity and starts one turn. The turn explicitly uses workspace-write with only that cwd writable, network disabled, temporary directory exclusions enabled and on-request approvals. Server-initiated requests go through an approval bridge that never approves anything by itself. The transport always refuses credential, login and attestation requests (for example `account/chatgptAuthTokens/refresh`, `attestation/generate`) before any handler sees them. The adapter holds only `item/commandExecution/requestApproval`, `item/fileChange/requestApproval` and confirmation-only `mcpServer/elicitation/request` (form mode without fields) for builder and repair runs on the session's own thread and turn; everything else (permission profiles, dynamic tools, user-input questions, legacy v1 approvals, foreign threads, Verifier and Supervisor runs) is refused as before. A held request becomes `approval.requested` with a stable id (`<runId>:<native request id>`), a kind (command, fileChange, tool), a human-readable summary bounded to 2000 characters (the command line and its cwd when outside the workspace, the proposed file paths with deletions marked, the network host and the agent's reason) and a conservative risk: credentials, privilege escalation or a cwd outside the workspace are critical; network access, installs, publishing, deletion, history rewriting or absolute/parent paths are high; read-only listing commands are low; anything else is medium; writes outside the workspace (`grantRoot`) are critical. `resolveApproval` answers once with the app-server shape (`{decision: "accept" | "decline"}`; elicitations `{action: "accept" | "decline"}`) and emits `approval.resolved`. Pending approvals are declined after 30 minutes, on stop (before `turn/interrupt`) and before any terminal event; a request the app-server withdraws (`serverRequest/resolved`) is forgotten unanswered. An answer that cannot be delivered is reported as rejected, never approved. The native executable and optional model come from local adapter configuration, not cloud commands.

Concurrent/retried starts share one reserved launch. Timed-out or failed launches are never replayed. Active messages use turn/steer with the expected turn identity; the Node advertises the `message` and `approval` capabilities. A Codex turn that completes ends the run (the adapter closes the connection), so a Codex run is never left waiting for a message: steering applies to the active turn only. Stop sends turn/interrupt and waits for a terminal notification: interrupted becomes stopped, completed remains completed, failed remains failed. An acknowledgement alone is not proof that execution stopped. An unconfirmed stop, lost connection or invalid activity requires reconciliation; it does not report a terminal failure that could release workspace ownership.

Subscriptions expose stable ordered normalized events with original Run/workspace/workstation provenance. Activity summaries come from the app-server thread items (`ThreadItem`, codex-cli 0.160.0) in `src/activity.ts`:

- `commandExecution` → `tool: "command"` with the command line (the `/bin/zsh -lc "…"` wrapper removed); the completion has `success` (completed with exit code 0) and, on failure, the suffix ` · exit code N`, ` · declined` or ` · failed`.
- `mcpToolCall` / `dynamicToolCall` → `tool: "mcp"` / `"tool"` with `server/tool` (`namespace/tool`); a failure appends ` · failed: <reason>` (at most 80 characters of the error message).
- `webSearch` → `tool: "web"` with `Search "<query>"`, `Open <url>` or `Find "<pattern>"`; `collabAgentToolCall` → `tool: "agent"` with a fixed label (for example "Start sub-agent").
- `reasoning`, `agentMessage`, `plan`, `contextCompaction`, review mode, image and sleep items → a short `run.activity` label when they start ("Thinking", "Writing reply", "Planning", …); their text is never uploaded.
- `fileChange` → `files.changed` with bounded relative paths inside the assigned workspace (unchanged); user messages and unknown item types produce nothing.

Every summary is redacted, flattened to one line and bounded to 500 characters (`safeSummary` in runtime-core) before it leaves the adapter. `redactSecrets` replaces with `***` the values of environment assignments, `--flag value`/`--flag=value` and JSON/YAML fields whose names look secret (token, secret, password, credential, cookie, api key, and whole-segment key, auth, session), `Authorization`/`Cookie`/`X-…-Token|Key` headers, `Bearer`/`Basic` credentials, `user:password@` in URLs, `curl -u user:password`, private key blocks, well-known token shapes (GitHub, GitLab, OpenAI-style `sk-`, Slack, AWS access key ids, Google API keys, JWTs) and long high-entropy runs (32 or more hex characters, or 20 or more mixed-case alphanumerics with digits). It is conservative: a 40-character commit id or a `--key` option value is hidden too; ordinary commands such as `pnpm test`, `git status` or `rg foo src` are unchanged. Approval summaries are redacted the same way (risk is still classified from the original command), and so is the final reply. The text of the last completed `agentMessage` item, trimmed, redacted and bounded to 8000 characters, becomes the `run.completed` summary (the agent's final reply; "Codex turn completed" when there was no message). Every event payload is kept under 15 KiB of JSON (the backend rejects payloads over 16 KiB) by dropping trailing paths, then shortening text. Command output, tool arguments and results, native errors, reasoning and earlier transcript text are not uploaded. Verifier and Supervisor turns use the read-only sandbox. Duplicate item notifications and foreign thread/turn activity are ignored. Terminal notifications settle once and close the native connection. Replays and snapshots are defensive copies.

Transport frames are capped at 1 MiB, pending requests at 64, and per-session event/item histories at 10,000. Malformed frames, child exit, stream errors and timeouts close the transport. Event overflow requires reconciliation. The adapter is a process-local first version: canResume, canDiscoverSessions and supportsSubagents are false. After Node replacement, an unknown native session is never silently recreated; the current reconciliation path retains workspace ownership. Durable native binding and history recovery are subsequent work.

Protocol baseline: codex-cli 0.160.0 and its generated TypeScript schema, checked against the [official app-server documentation](https://learn.chatgpt.com/docs/app-server). Generate version-matching bindings with `codex app-server generate-ts --out <scratch-directory>` when updating the adapter. Generated vendor files remain development references, not domain contracts.

Validation: all 67 local tests, typecheck, dependency boundaries and production build pass. Codex passes the shared runtime contract suite plus controlled lifecycle tests covering concurrent start, assignment and sandbox parameters, tool/file normalization, duplicate/foreign notifications, steering, confirmed/unconfirmed stop, traversal, connection loss and ambiguous retry handling. A real isolated CLI handshake and thread creation verified initialization, assigned cwd and native session identity using a temporary CODEX_HOME without the existing login; the temporary files and process were removed afterward.

The controlled Node integration test also passes through a real isolated Git worktree, LocalStateStore, RuntimeManager, ControlPlaneDriver and convex-test settlement; native session metadata persists, the durable outbox drains, and the canonical checkout remains unchanged.

Authenticated Mac acceptance passed on 2026-10-05: the existing ChatGPT login was used only in a temporary isolated profile without user plugins/MCP/config. One minimal inference completed in an assigned real Git worktree, emitted a terminal normalized event, and left canonical HEAD/status unchanged. The authentication copy and fixture were removed. Reproduce with `apps/node/node_modules/.bin/tsx scripts/codex-acceptance.mts --authenticated`. This native inference acceptance is distinct from phone pairing/device E2E. Delayed completion is covered by the Node integration test; the driver observes the terminal native snapshot before persisting completion and releasing its local lease. Production enrollment, durable resume/discovery and continuous Node supervision remain future work. Native plugins/MCP configuration must be governed by local workstation policy before enabling production execution; a sandbox declaration alone does not constrain external tools.

Approval acceptance passed on 2026-10-06 with codex-cli 0.160.0 (`ZAMOLXIS_AUTHENTICATED_ACCEPTANCE=1 pnpm vitest run tests/approvals-steering.test.ts -t "real Codex approval"`): in a temporary profile and a disposable repository worktree, a builder asked to run `curl` with escalated permissions produced one `item/commandExecution/requestApproval`, normalized as a high-risk command approval (`Run: /bin/zsh -lc "curl …"` plus the agent's reason); it was rejected, the turn completed and the repository HEAD was unchanged. The approve path, file change approvals, MCP elicitations and steering against a real Codex turn are covered only by controlled tests.

Activity summaries (2026-10-06) are covered by controlled tests: per-item normalization, failure suffixes, shell unwrapping, payload bounds and a redaction table of secret patterns and ordinary commands; the Run detail timeline renders command lines as monospace with the failure reason as muted text. A real authenticated codex-cli 0.160.0 turn (2026-10-06, temporary profile, disposable repository worktree, canonical HEAD/status unchanged) asked to run two commands produced `tool.started`/`tool.completed` with `git status --short` (success) and `ls fixture.txt missing-file.txt · exit code 1` (failure), "Writing reply" labels and the final reply; MCP, web search, sub-agent and redaction paths are covered only by controlled tests. Item shapes of other codex-cli versions are not guaranteed; unknown item types are ignored.
